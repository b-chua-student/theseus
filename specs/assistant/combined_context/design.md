# Design - Compare a manuscript with selected library sources

## Components and Flow

1. At Send, the editor captures the question, exact quote, checked contexts and current unsaved draft text if Manuscript is checked.
2. The exchange route authenticates the writer, checks project membership and conversation ownership by project, then validates the request.
3. ChatService restricts retrieval to selected library entries belonging to the project. It ranks passages and builds the model input from excerpts that fit alongside the question, quote, draft and history.
4. The model compares the claim with the supplied excerpts and cites their keys. The service resolves the citations and saves the exchange and selection on success.
5. The chat panel renders sanitized answer text and displays the resolved source titles beside the cited findings.

## Data and Interfaces

| Boundary | Data and interpretation |
| --- | --- |
| Editor to exchange route | Send the question in `query`, the exact selected passage in `quote`, and the live draft in `manuscript_text` when selected. A combined request carries independent Web and Manuscript settings and explicit library entry UUIDs in `source_ids`. A quote-only draft contribution leaves the rest of the draft private. |
| Legacy request or saved chat to service | Decode `none` as Web alone. D-006 proposes restoring `manuscript` as Manuscript alone and `source_library` as the saved sources with Web off. For a legacy all-library record with null IDs, use a snapshot of the currently indexed project library. |
| Retrieval to model | Supply each admitted passage with an exchange-local key, library entry ID, title, location and text. Label the quote as the comparison target and retain its wording separately from the question. |
| Service to chat panel | Return the answer and resolved citations. For each cited key, look up the ID, title and location in this exchange’s admitted passages. Discard unknown keys. The editor uses the resolved title when displaying a citation. |

## Evidence Outcomes

If the draft reports 18 participants, a selected study reporting 18 supports that figure. A study reporting 24 for the same trial supplies conflicting evidence. A study reporting 18 adults qualifies a claim about the whole cohort. Attribute each finding to its supplied passage. When Web is enabled, identify general knowledge separately.

## Open Questions

The intake proposes the following answer behavior. These proposals await confirmation.

| Retrieval result | Proposed answer |
| --- | --- |
| A selected source could not be searched | Name the source and say it could not be checked. Continue with the usable evidence. |
| Search completed and no passage met the relevance cutoff | Name the source and say the search found no relevant passage. |
| A source matched, but none of its eligible passages fit | Name the source and explain that its evidence exceeded the available space. Cite only passages supplied to the model. |

If none of the selected sources supplies usable evidence, say the claim could not be verified from the selection. A contradiction requires a conflicting passage.

Use the live draft text directly instead of indexed manuscript chunks. | `requests.py`, `routes.py`, `ChatService` (`chat.py`), `container.py` | R-002, R-005 |
| D-003 | Embed the question, together with the quoted claim when present, and query eligible passages per source, so one source cannot use up the shared top-k. Attach the library entry ID and title to each supplied passage by adding the title to `RetrievedChunk` or to a new evidence value object. Add a semantic `EmbeddingGenerator` adapter (Gemini via `google-genai`) and wire it in `container.py`. The only generator today is the hash-based `InMemoryEmbeddingGenerator`. | D-004 | Extend the `ChatModel` port so it receives the draft, the quote, the question and labelled source excerpts. Each admitted excerpt carries an exchange-local citation key, the library entry ID, the source title, the passage text and its location. Mark the quote as the comparison target, even when the draft contains similar wording and even when Manuscript is unchecked. The model cites excerpts by key. The service looks up each cited key among the admitted excerpts to obtain its source ID, title and location, and discards keys that match none, so only supplied library evidence is cited. Return the resolved citations with the answer, so the exchange route returns more than `{answer}`. The editor renders the answer through its existing sanitized Markdown path and shows the source titles from the citations. | `ChatModel` port, `GeminiChatModel`, `ChatService`, `routes.py`, `value_objects.py`, `ChatPanel.svelte`, test `FakeChatModel` | R-003, R-004 |
| D-005 | One Context dropdown replaces the three scope buttons and the separate source picker. It has a scrollable, title-filtered source list and fixed Web, Manuscript and Clear selection controls. A new chat starts with Web alone, and the closed button summarizes the selection (for example "Web" or "Manuscript + 2 sources"). Checking or unchecking takes effect immediately with no Apply step. Arrow keys move focus, Space toggles the focused item, and Escape closes the dropdown and returns focus to the Context button. Checking or unchecking Manuscript or a source leaves Web as it was. Unchecking the last checked item, or choosing Clear selection, leaves only Web checked. Filtering never clears checked items. Quoting never changes the checked items. Remove the per-selection `sessions` key, and keep conversation identity independent of filtering, quoting and selection changes. | `ChatPanel.svelte` or a new Context dropdown component, `chat.js`, `sources.js` | R-001 |
| D-006 | Encode Web and Manuscript independently of the selected source UUIDs. Web alone keeps the existing scope `none`, sent with empty manuscript text and null source IDs. Accept selections above 1,000 IDs without truncation and batch downstream work. On a successful exchange only, store the Web and Manuscript flags and the selected ID and title pairs on the `Conversation`. A failed send leaves the previous selection stored. Add defaults for old Mongo documents and return the new fields from `_conversation_json`. On restore, show a record saved with scope `none` as Web alone. Decode a legacy `manuscript` record as Manuscript with Web off, and a legacy `source_library` record as its sources with Web off. For a legacy `source_ids` of null (all library), snapshot the currently indexed project library when the chat is reopened. Resolve this mapping at read time and persist the normalized selection after the next successful exchange. Name a removed source from its stored title and keep the remaining choices checked. | `Conversation` (`aggregates.py`), `InMemoryConversationRepository`, `MongoConversationRepository`, `_conversation_json` in `routes.py`, `requests.py`, `ChatPanel.svelte` | R-001, R-005 |
| D-007 | Attempt to search every selected source and isolate a failed search to its source. Apply the calibrated cosine threshold inclusively (at or above) to `RetrievedChunk.score`. Calibrate the cutoff with the semantic embedding model used for indexing: label supporting, qualifying, conflicting and unrelated passage pairs, choose the cutoff, and check it on held-out pairs. Treat conflicting passages as relevant. Keep the threshold and the passage budget in configuration. Allocate eligible passages in rounds across sources, trying smaller fitting passages before marking a source omitted for capacity. Compute the evidence budget from the configured model window minus tokens for instructions, history, question, selected draft, quote, formatting and reserved response. Count the assembled request through a new token counter port before dispatch. Preserve per-source search and passage-admission results for the proposed reporting behavior under Open Questions. | `ChatService` and `_retrieve`, `VectorStore` adapters, a new token counter port with a Gemini-backed adapter, `container.py` | R-003, R-005 |
| D-008 | Pass the named per-source outcomes and only the admitted excerpts to the model. Distinguish support, qualification and conflicting facts. The proposed handling of evidence gaps is specified under Open Questions. Web enables model knowledge and adds no browsing, and the answer labels that knowledge separately from findings attributed to selected sources. With Web off, instruct the model to base factual findings only on the manuscript and the selected sources. | `ChatModel` port, `GeminiChatModel` system instruction and prompt builder, `ChatService` | R-003 |
| D-009 | "All indexed sources" is the only bulk-selection checkbox in the dropdown. Checking it copies the project's indexed library source IDs once, including entries hidden by the title filter, and preserves Web and Manuscript. Unchecking one source clears its indicator and checking every source restores it, derived from the indexed IDs of the whole project list. It is disabled when no sources are indexed. Sources indexed afterward stay unchecked until the writer checks them. The assistant context exposes a read endpoint that returns the project's searchable library source IDs from `IndexedDocumentRepository`. It excludes manuscript documents, which `OnManuscriptSaved` also indexes in the same repository, by intersecting with the project's active source IDs (the `source_ids` callable in `container.py`). The frontend joins those IDs with the titles from `listSources`, so `assistant` and `src_lib` never import each other's services. | `ChatPanel.svelte` or the Context dropdown component, `sources.js`, assistant `routes.py`, `IndexedDocumentRepository` | R-001 |

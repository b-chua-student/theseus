# Design - Compare a manuscript with selected library sources

Use one row per design decision. Each row names the affected components and the requirements from [requirements.md](requirements.md) that it supports.

## Design

| ID | Decision | Components | Requirements |
| --- | --- | --- | --- |
| D-001 | Capture the question, the checked library entry IDs and the exact editor quote at send time. Send the question in `query` and the quote in its own `quote` field, not appended to the question text. Read `editor.getText()` and send it in `manuscript_text` only when Manuscript is checked. When Manuscript is unchecked, a quote still travels as its own field and no other draft text is sent. Send the snapshot in one exchange on the active conversation. | `ChatPanel.svelte`, `frontend/src/lib/api/chat.js`, `AskRequest` (`requests.py`), exchange route (`routes.py`) | R-001, R-002, R-004, R-005 |
| D-002 | Normalize the request into independent manuscript and library inputs. Keep the existing authentication and project-membership checks on the conversation blueprint, verify that the conversation belongs to the project, and validate the request before calling `ChatService`. Decode the legacy `context_scope` values (`none`, `manuscript`, `source_library`) at the API boundary. In `ChatService._retrieve`, keep intersecting the requested IDs with the active sources of the authorized project (the `source_ids` callable wired in `container.py`) before any vector query. Use the live draft text directly instead of indexed manuscript chunks. | `requests.py`, `routes.py`, `ChatService` (`chat.py`), `container.py` | R-002, R-005 |
| D-003 | Embed the question, together with the quoted claim when present, and query eligible passages per source, so one source cannot use up the shared top-k. Attach the library entry ID and title to each supplied passage by adding the title to `RetrievedChunk` or to a new evidence value object. Add a semantic `EmbeddingGenerator` adapter (Gemini via `google-genai`) and wire it in `container.py`. The only generator today is the hash-based `InMemoryEmbeddingGenerator`. Use the same model for indexing and queries. Re-embed existing documents through the `IngestionWorker` reindex path when the model changes, in whichever `VectorStore` is wired (`InMemoryVectorStore` by default, `ChromaVectorStore` when configured). | `ChatService`, new Gemini embedding adapter, `IngestionWorker` and the source and manuscript handlers, `VectorStore` port and adapters, `value_objects.py`, `container.py` | R-003, R-004, R-005 |
| D-004 | Extend the `ChatModel` port so it receives the conversation history, the draft, the quote, the question and labelled source excerpts. Each admitted excerpt carries an exchange-local citation key, the library entry ID, the source title, the passage text and its location. Mark the quote as the comparison target and keep its wording separate from the question, even when the draft contains similar wording and even when Manuscript is unchecked. The model cites excerpts by key. The service looks up each cited key among the admitted excerpts to obtain its source ID, title and location, and discards keys that match none, so only supplied library evidence is cited. Return the resolved citations with the answer, so the exchange route returns more than `{answer}`. The chat panel renders the answer through its existing sanitized Markdown path and shows the source titles from the citations. | `ChatModel` port, `GeminiChatModel`, `ChatService`, `routes.py`, `value_objects.py`, `ChatPanel.svelte`, test `FakeChatModel` | R-003, R-004 |
| D-005 | One Context dropdown replaces the three scope buttons and the separate source picker. It has a scrollable, title-filtered source list and fixed Web, Manuscript and Clear selection controls. A new chat starts with Web alone, and the closed button summarizes the selection (for example "Web" or "Manuscript + 2 sources"). Checking or unchecking takes effect immediately with no Apply step. Arrow keys move focus, Space toggles the focused item, and Escape closes the dropdown and returns focus to the Context button. Checking or unchecking Manuscript or a source leaves Web as it was. Unchecking the last checked item, or choosing Clear selection, leaves only Web checked. Filtering never clears checked items. Quoting never changes the checked items. Remove the per-selection `sessions` key, and keep conversation identity independent of filtering, quoting and selection changes. | `ChatPanel.svelte` or a new Context dropdown component, `chat.js`, `sources.js` | R-001, R-004, R-009 |
| D-006 | Encode Web and Manuscript independently of the selected source UUIDs. Web alone keeps the existing scope `none`, sent with empty manuscript text and null source IDs. Accept selections above 1,000 IDs without truncation and batch downstream work. On a successful exchange only, store the Web and Manuscript flags and the selected ID and title pairs on the `Conversation`. A failed send leaves the previous selection stored. Add defaults for old Mongo documents and return the new fields from `_conversation_json`. On restore, show a record saved with scope `none` as Web alone. The intake does not cover other legacy records, so this design decodes a legacy `manuscript` record as Manuscript with Web off and a legacy `source_library` record as its sources with Web off. For a legacy `source_ids` of null (all library), it snapshots the currently indexed project library when the chat is reopened. Resolve this mapping at read time and persist the normalized selection after the next successful exchange. Name a removed source from its stored title when available and keep the remaining choices checked. | `Conversation` (`aggregates.py`), `InMemoryConversationRepository`, `MongoConversationRepository`, `_conversation_json` in `routes.py`, `requests.py`, `ChatPanel.svelte` | R-001, R-005, R-008, R-009, R-010 |
| D-007 | Attempt to search every selected source and isolate a failed search to its source. Apply the calibrated cosine threshold inclusively (at or above) to `RetrievedChunk.score`. Calibrate the cutoff with the semantic embedding model used for indexing: label supporting, qualifying, conflicting and unrelated passage pairs, choose the cutoff, and check it on held-out pairs. Treat conflicting passages as relevant. Keep the threshold and the passage budget in configuration. Allocate eligible passages in rounds across sources, trying smaller fitting passages before marking a source omitted for capacity. Compute the evidence budget from the configured model window minus tokens for instructions, history, question, selected draft, quote, formatting and reserved response. Count the assembled request through a new token counter port before dispatch. Replace the blanket `except Exception` in `_retrieve` with per-source outcomes (unavailable, searched without a match, omitted for capacity) and pass them to D-008. | `ChatService` and `_retrieve`, `VectorStore` adapters, a new token counter port with a Gemini-backed adapter, `container.py` | R-003, R-005, R-007, R-008 |
| D-008 | Pass the named per-source outcomes and only the admitted excerpts to the model, and attribute each finding to its supplied passage. Distinguish support, qualification and conflicting facts. For example, if the draft reports 18 participants, a study reporting 18 supports it, a study reporting 24 for the same trial conflicts, and a study reporting 18 adults qualifies a claim about the whole cohort. Report each gap: name an unavailable source and say it could not be checked; name a source searched without a match and say no relevant passage was found; name a source omitted for capacity and say its evidence exceeded the available space, without citing its passages. Continue with the usable evidence. If none is usable, say the claim could not be verified from the selection. A contradiction requires a conflicting passage. Web enables model knowledge and adds no browsing, and the answer labels that knowledge separately from findings attributed to selected sources. With Web off, instruct the model to base factual findings only on the manuscript and the selected sources. | `ChatModel` port, `GeminiChatModel` system instruction and prompt builder, `ChatService` | R-001, R-003, R-007 |
| D-009 | "All indexed sources" is the only bulk-selection checkbox in the dropdown. Checking it copies the project's indexed library source IDs once, including entries hidden by the title filter, and preserves Web and Manuscript. Unchecking one source clears its indicator and checking every source restores it, derived from the indexed IDs of the whole project list. It is disabled when no sources are indexed. Sources indexed afterward stay unchecked until the writer checks them. The assistant context exposes a read endpoint that returns the project's searchable library source IDs from `IndexedDocumentRepository`. It excludes manuscript documents, which `OnManuscriptSaved` also indexes in the same repository, by intersecting with the project's active source IDs (the `source_ids` callable in `container.py`). The frontend joins those IDs with the titles from `listSources`, so `assistant` and `src_lib` never import each other's services. | `ChatPanel.svelte` or the Context dropdown component, `sources.js`, assistant `routes.py`, `IndexedDocumentRepository` | R-001, R-006 |

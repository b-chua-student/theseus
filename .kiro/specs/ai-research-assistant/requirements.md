# Requirements Document: AI Research Assistant (THESEUS-6)

## 1. Introduction & Overview

The **AI Research Assistant** ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160) / Epic Key: `THESEUS-6`) provides an integrated Retrieval-Augmented Generation (RAG) assistant for the Theseus research manuscript editor. The assistant answers user questions about a manuscript and its attached research sources using Google Gemini.

When domain events (`ManuscriptSaved`, `SourceAdded`, and `SourceRemoved`) fire, manuscript sections and reference sources are asynchronously chunked, embedded, and indexed (or de-indexed). Users can query the indexing status of a manuscript, create assistant conversations, and submit natural-language questions (`Exchange` records) that retrieve relevant context chunks and synthesize grounded responses via Google Gemini.

## 3. Glossary

* **Manuscript**: The primary research document aggregate being authored by a user within a Theseus project.
* **Source**: A supplementary reference document or citation source attached to a manuscript.
* **Chunk**: A discrete segment of text extracted from a manuscript or source, paired with metadata (`manuscript_id`, `source_id`, chunk index) and a vector embedding.
* **Ingestion Worker**: The background/asynchronous service (`domain/assistant/services/ingestion_worker.py`) responsible for chunking text, generating embeddings via Google Gemini, and updating the vector store and indexing status ([THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
* **Conversation**: A domain aggregate representing an interactive Q&A session scoped to a specific `manuscript_id` ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161)).
* **Exchange**: A single question-and-answer pair within a `Conversation`, storing the user prompt, retrieved context references, and the whole response generated by Google Gemini ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164)).

## 4. Functional Requirements

### Requirement 1: Event-Driven Manuscript Indexing ([THES-163](https://theseus-inc.atlassian.net/browse/THES-163))

**User Story:** As a researcher editing a manuscript, I want my saved manuscript content to be indexed automatically in the background so that the AI Research Assistant always answers using my latest draft.

#### Acceptance Criteria

1. WHEN a `ManuscriptSaved` event is emitted, THE `on_manuscript_saved.py` handler SHALL enqueue or trigger an asynchronous ingestion job in `ingestion_worker.py` for the target `manuscript_id` ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
2. WHEN the ingestion worker processes a manuscript, THE `ingestion_worker.py` service SHALL split the manuscript content into chunks, generate vector embeddings via the Gemini embedding adapter, and replace any stale manuscript chunks for that `manuscript_id` in the vector store ([THES-162](https://theseus-inc.atlassian.net/browse/THES-162), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
3. WHILE manuscript ingestion is actively running, THE system SHALL record the manuscript's indexing status as `INDEXING` (or in-progress) ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
4. WHEN manuscript ingestion completes without error, THE system SHALL update the manuscript's indexing status to `INDEXED` (or ready) and record the updated chunk count/timestamp ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).

### Requirement 2: Event-Driven Source Indexing & De-Indexing ([THES-163](https://theseus-inc.atlassian.net/browse/THES-163))

**User Story:** As a researcher managing bibliography and reference materials, I want added sources to be indexed and removed sources to be purged automatically so that assistant answers only draw from active sources.

#### Acceptance Criteria

1. WHEN a `SourceAdded` event is emitted, THE `on_source_added.py` handler SHALL invoke `ingestion_worker.py` to chunk the source text, compute embeddings via the Gemini embedding adapter, and store the source chunks associated with the `manuscript_id` and `source_id` ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
2. WHEN a `SourceRemoved` event is emitted, THE `on_source_removed.py` handler SHALL remove all vector store chunks matching the removed `source_id` so they are excluded from subsequent RAG retrievals ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
3. IF a `SourceRemoved` event references a `source_id` with no existing indexed chunks, THEN THE `on_source_removed.py` handler SHALL complete idempotently without raising an unhandled exception ([THES-163](https://theseus-inc.atlassian.net/browse/THES-163), [THES-166](https://theseus-inc.atlassian.net/browse/THES-166)).

### Requirement 3: Manuscript Indexing-Status Reporting ([THES-163](https://theseus-inc.atlassian.net/browse/THES-163), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165))

**User Story:** As a researcher opening the AI assistant panel, I want to see whether my manuscript and sources have finished indexing so that I know when RAG answers reflect my latest changes.

#### Acceptance Criteria

1. WHEN a client queries the indexing status for a valid `manuscript_id`, THE `get_indexing_status.py` service SHALL return the current indexing state (e.g., `PENDING` / `INDEXING` / `INDEXED` / `FAILED`) and associated status details ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
2. IF a client requests the indexing status with a malformed `manuscript_id` UUID, THEN THE API layer SHALL return HTTP `400 Bad Request` ([THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
3. IF a client requests the indexing status for a `manuscript_id` that does not exist, THEN THE API layer SHALL return HTTP `404 Not Found` ([THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).

### Requirement 4: Conversation Creation & Management ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165))

**User Story:** As a researcher, I want to start a conversation thread scoped to my manuscript so that I can ask questions and review my exchange history within that session.

#### Acceptance Criteria

1. WHEN a client submits a valid request to create a conversation for a `manuscript_id`, THE system SHALL instantiate a new `Conversation` domain aggregate, persist it in the repository, and return the serialized conversation with HTTP `201 Created` (or `200 OK`) ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
2. WHEN a conversation is created, THE `Conversation` entity SHALL initialize with an empty ordered list of `Exchange` records and a valid `manuscript_id` association ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161)).
3. IF the conversation creation payload fails Pydantic schema validation (such as missing or invalid `manuscript_id` or unexpected fields), THEN THE API layer SHALL reject the request with HTTP `400 Bad Request` ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).

### Requirement 5: RAG Question Answering & Exchanges ([THES-162](https://theseus-inc.atlassian.net/browse/THES-162), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165))

**User Story:** As a researcher, I want to ask a question in an active conversation and receive a complete, grounded answer synthesized from my manuscript and sources via Google Gemini.

#### Acceptance Criteria

1. WHEN a user submits a non-empty question to an existing `conversation_id`, THE `chat.py` service SHALL embed the query via the Gemini embedding adapter and query the vector store for the top-k most relevant chunks scoped to the conversation's `manuscript_id` ([THES-162](https://theseus-inc.atlassian.net/browse/THES-162), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164)).
2. WHEN relevant chunks are retrieved (or when the vector store returns an empty list if no chunks match), THE `chat.py` service SHALL construct a grounded prompt containing the retrieved context and conversation exchanges, invoke the Google Gemini chat adapter, and receive a complete (non-streaming) answer ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164)).
3. WHEN the Gemini adapter returns an answer, THE `chat.py` service SHALL append a new `Exchange` record (question, answer, citations/chunks, timestamp) to the `Conversation` aggregate, persist the updated conversation, and return the complete response ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
4. IF the user submits an empty or whitespace-only question string, THEN THE system SHALL reject the input with HTTP `400 Bad Request` ([THES-161](https://theseus-inc.atlassian.net/browse/THES-161), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
5. IF the specified `conversation_id` does not exist, THEN THE system SHALL return HTTP `404 Not Found` ([THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).

### Requirement 6: Provider-Failure & Configuration-Error Handling ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165))

**User Story:** As a developer and end user, I want clear, structured error handling when the Google Gemini API key is missing or when upstream embedding/chat calls fail so that the application degrades gracefully without corrupting conversation state.

#### Acceptance Criteria

1. IF the Google Gemini API configuration (such as the API key or model configuration) is missing or invalid when an indexing or chat operation is invoked, THEN THE system SHALL raise a typed configuration error and return an appropriate error status (such as HTTP `500` or `503 Service Unavailable`) with a clear diagnostic message ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
2. IF the upstream Google Gemini API fails during question answering (e.g., timeout, quota exhaustion, or network error), THEN THE `chat.py` service SHALL surface a provider-failure exception without persisting an incomplete `Exchange` to the `Conversation`, and the API layer SHALL return HTTP `502 Bad Gateway` / `503 Service Unavailable` ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-164](https://theseus-inc.atlassian.net/browse/THES-164), [THES-165](https://theseus-inc.atlassian.net/browse/THES-165)).
3. IF the upstream embedding provider fails during asynchronous manuscript or source ingestion, THEN THE `ingestion_worker.py` service SHALL catch the provider failure, mark the manuscript's indexing status as `FAILED` with the failure reason, and prevent unhandled worker crashes ([THES-160](https://theseus-inc.atlassian.net/browse/THES-160), [THES-163](https://theseus-inc.atlassian.net/browse/THES-163)).
